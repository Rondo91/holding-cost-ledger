# 持有成本账本 · 产品初步设计 UX 评审

| 项目 | 内容 |
|---|---|
| 评审对象 | 《产品初步描述.docx》（项目根目录） |
| 评审视角 | 用户体验专项（非 PRD、非竞调） |
| 评审方式 | 基于文档自身数据与逻辑（12 人访谈、指标表、交互原则），n=0 前提下不假设任何用户行为数据 |
| 产出 | 6 条优化点 + 4 组关键议题的方案对比 |

---

## 一、设计里已经做对的事（面试可讲的素材）

1. **反馈两问直接验证"结果是否影响决策"而非满意度**——把反馈机制和产品价值主张对齐，验证的是"有没有用"而不是"讨不讨喜"。
2. **S 为空时显示"未计入残值"而不是 0 元**——避开了最常见的假精度错误：0 会把"信息缺失"伪装成"计算结果"。
3. **放弃清单具体且每条对应真实诱惑**（不推荐卖 / 不自动搜价 / 不判耐用度）——说明边界是想出来的，不是没做才放弃的。
4. **截图识别字段标"待确认"且不自动写入计算**——AI 不确定性的责任归属处理正确：AI 猜错一个数字就会摧毁"可信工具"的定位。
5. **二手价用区间而非单点、所有数值标注"估算"**——与"可信、清晰的决策工具"的自我定位自洽。

## 二、值得优化的点（按重要性从高到低）

### 1. 必填项与访谈主流需求错位，文档没有正面处理这个张力

- **依据**：访谈 7/12 第一反应是查当前售价（1、2、3、9、10、11），仅 3/12 关注买价（4、5、6），仅 2/12 做比较；而必填项是"购买日期 + 实付金额"。更尖锐的是 #2 原话"我都不记得当初买多少钱了"——这类用户在当前必填设计下**根本无法完成核心流程**。
- **为什么重要**：对占多数的 A 类用户，工具回答的问题不是他们问的问题。首屏第一道输入就是门槛，而它服务的是少数需求。
- **建议**：① 给"记不清买价/日期"一条降级路径（见议题一）；② 在"我想服务的人群"里明确承认：本工具不解决"估价"（那是闲鱼的事），解决"算账"——这个取舍目前只藏在放弃清单第 2 条的字缝里；③ 首屏文案直接接住 A 类用户："想先知道能卖多少？去闲鱼搜同款成交价，回来填这里"——把产品边界变成引导，而不是沉默。

### 2. 主数字选错了决策对象：日均成本是沉没成本指标，会强化而非纠正非理性决策

- **依据**：设计定"日均成本、估算保值率"为首版最重要结果；访谈 #6"每天成本很高，我可能继续用"——教科书式沉没成本谬误：已花的钱不构成继续持有的理由，影响决策的应是未来成本和当前残值。
- **为什么重要**：产品目标写着"更有依据地决定继续使用、出售还是更换"，但主打指标在心理上把用户推向"继续用"（日均越摊越低）——与产品目标直接冲突。
- **建议**：见议题二。

### 3. "每输入一个关键字段就即时更新"在金额输入的中间态是灾难

- **依据**：交互原则原文"每输入一个关键字段就即时更新结果"。
- **场景**：输入"5999"会经过 5、59、599 三个中间态；持有天数几百天时，日均成本从"5 元/天"跳到"59 元/天"再落回"12 元/天"；同时 5、59 可能触发"金额过低"校验——**输入过程中弹错误是最经典的表单 UX 错误，惩罚了还没输完的用户**。
- **建议**：见议题三。

### 4. 流程页数与 60 秒目标自相矛盾，独立反馈环节打断在结果刚出现的那一刻

- **依据**：流程为输入页 → 基础结果页 → 补充残值页 → 完整结果页（→ 反馈页），共 5 屏；指标却要求中位完成时长 60 秒内。
- **为什么重要**：每换一屏都是一次注意力成本。更根本的是反馈时机：用户刚看到数字、还没拿它做任何判断，就被问"这个结果是否帮助你判断下一步"——**此刻的回答反映的是数字好不好看，不是有没有用**。
- **建议**：残值补充并入结果页（基础结果下方直接放"补充当前售价"输入区，填了立即变完整结果，不跳页）；反馈改非阻断且时机后移（见议题四）。

### 5. 关键异常态没有被定义，"输入错误和异常状态处理"只是一句话

- **具体缺口**：① 购买日期晚于今天（D 为负，max(1,…) 只兜底 D=0）；② 实付金额为 0（奖品/礼物，回收率 S/P 除零）；③ S>P（回收率超 100%，展示口径未定义）；④ 持有天数极短（D=1 时日均购入成本 = 全额，数字冲击极强且无解释）；⑤ **日期精度门槛**——用户通常记得"2022 年双十一"而非"2022 年 11 月 7 日"，要求精确到日制造了本可不存在的输入门槛，而 ±3 天对结果影响可忽略。
- **建议**：日期控件提供"大约时间"档（年 + 月，D 按月中值算并标"估算"）；每个异常态配一句用户能懂的文案，而非通用"输入有误"。

### 6. 访谈结论的计数方式经不起追问（面试风险，不是产品缺陷）

- "关注当前售价 7 人"里含 #4、#5，而这两位同时被计入"关注购买价 3 人"——同一人被拆进两组，交叉计数让 7/12、3/12、2/12 不可加总；#9 同时记 A/C。n=12 本来就小，**结论方向没错，但表格呈现方式会被有统计背景的面试官追问**。
- **建议**：改成互斥分组（按第一反应归属），或直接呈现"用户原话 → 需求"映射表；或加一句"交叉计数、非互斥"即可自洽。

## 三、关键问题的两个可选方案（供选择）

### 议题一：必填项错位怎么办

**方案 A：保持"日期 + 买价"必填，加降级路径。** 日期支持"大约时间"（年 + 月）；买价支持"不记得了" → 填区间或档位，输出相应标注"估算区间"。
- 优点：计算主线不变，产品差异化（固定口径）保住；#2 类用户不再被锁在门外。
- 代价：模糊输入必然更模糊，"可信工具"要让渡一点精度；表单状态变多。

**方案 B：重排流程，售价前置或双入口。** 首屏先填"当前二手价"，买价日期可选/后补；或首页分流"我想算持有成本 / 我想知道该不该卖"。
- 优点：接住 7/12 的主流第一反应，首屏动机匹配。
- 代价：没有买价算不出任何成本指标——A 类用户"能卖多少"的问题本工具无法回答（那是闲鱼的功能且已明确放弃），前置售价只是把闲鱼的答案搬进来，产品退化成记事本；双入口增加首页决策成本，MVP 要养两条流程。

**评审推荐：A。** 产品的差异化恰恰建立在"我有别人没有的口径"上，B 等于把定位让渡给放弃清单里已否掉的方向。但 A 必须配上首屏对 A 类用户的文案接住（优化点 1 建议③），否则错位只是被掩盖。

### 议题二：结果页主数字

**方案 A：净持有支出（P−S）做主数字**，日均净成本和回收率次之；S 为空时日均购入成本为主。配一句固定文案："已支付的金额不影响你接下来的决定，当前回收价才影响。"
- 优点：#4 原话是"主要想知道自己亏了多少"——主数字直接用用户自己的语言；总额的决策相关性强于日均；固定文案顺手纠正沉没成本偏见。
- 代价：日均成本降级，#6 类用户的核心数字变小；文案有说教风险。

**方案 B：维持日均为主数字**，但只显示"日均净成本"（S 存在时），同屏固定展示回收率，弱化日均购入成本。
- 优点：保留"每天才 X 元"的直觉冲击，这是本产品相对"自己拿计算器算"的核心体验差异。
- 代价：不解决沉没成本导向，只是让数字诚实一点。

**评审推荐：A。** 文档自己定义的目标是"帮助决定继续用/出售/换新"，日均成本在这个决策里只提供情绪价值；选 A 是让主数字为产品目标服务，选 B 是为数字的传播性服务。这个取舍本身就是面试里的好故事。

### 议题三：即时更新的中间态

**方案 A：字段级更新。** 更新时机从"每次按键"改为"字段完成"——失焦、回车或日期控件收起时触发；输入中不校验、不报错、不更新。
- 优点：实现最简单，状态可预期，中间态完全消失。
- 代价：失去"边填边出结果"的即时感——而这恰是设计原则里明确要的体验。

**方案 B：保留即时更新，加三重防护。** ① 金额输入 300ms 防抖后才重算；② 结果区只在关键字段全部有效时渲染，否则显示占位"待填写完整"；③ 范围校验只在失焦后触发，输入中静默。
- 优点：保住即时感，所有中间态被吸收。
- 代价：交互细节多，防抖参数没有数据只能发布后凭完成率回溯调校。

**评审推荐：B。** 60 秒完成目标意味着流程必须零困惑，失焦更新反而制造新的等待感；B 的代价集中在实现层而非体验层。开发时间紧可先上 A 再迭代 B。

### 议题四：反馈的形态与时机

**方案 A：并入结果页的非阻断反馈条。** 结果页停留若干秒后底部滑出："这个数字改变你的想法了吗？（没有/有一点/改变了）+ 你接下来更可能：继续用/查价/出售/换新/不确定"，可关闭、不打断。
- 优点：不打断流程；第一问措辞比"是否帮助判断"更诚实（承认可能没用）；回收阻力最小。
- 代价：底部滑层在移动端可能遮挡结果数字，需要避让设计；滑出时机会打扰正在看公式的用户。

**方案 B：保留独立反馈环节，但移到用户主动结束之后**——点分享/关闭/再次计算时才问；或只问一题（接下来打算），"是否帮助"留给后续回访验证。
- 优点：反馈发生在用户真正做过判断之后，数据质量更高；一题比两题完成率高。
- 代价：多数用户可能永远不触发"结束"动作，15% 反馈率目标更难达成；最有验证价值的问题被推迟或砍掉。

**评审推荐：A，但把两问砍成一问。** 只留"你接下来更可能：…"——"这个结果是否帮助你判断"无论何时问都带引导性（用户面对工具倾向给面子答案），行为选项题才接近真实决策信号。若坚持两问，第一问改成"改变想法了吗"的中性措辞。

## 四、与当前线上版本（v1.3）的对照

> 主理人交叉核对备注：初步设计是 v1.0 之前的输入文档，部分评审点在已上线的实现中已被解决。以下标注每条的现状，避免对已解决的问题重复行动。

| 评审点 | 当前实现状态 | 结论 |
|---|---|---|
| 1. 必填项错位 / 记不清买价的用户 | 未做降级路径；PRD 已正面写出"买价优先"的取舍理由，但首屏没有对 A 类用户的引导文案 | **仍成立，待决策（议题一）** |
| 2. 主数字与沉没成本 | 完整结果区展示净持有支出/日均净支出/回收率，但视觉层级未明确以净持有支出为主数字，也没有纠偏文案 | **部分成立，待决策（议题二）** |
| 3. 输入中间态 | **已解决**：v1.1 起视觉更新 200ms 防抖、结果出现与埋点等 900ms 停稳/失焦，校验不再在输入中触发——比议题三两个方案都更完整（双层时间线） | 已解决，无需行动 |

## 五、附带提醒

所有指标初期目标（60% / 40% / 60 秒 / 15%）在 n=0 前提下都是假设。面试时主动讲"这是上线前预设的证伪线，不是 KPI"——比把假设讲成承诺更经得起追问。
