## 判定口径

初期文稿与现状的关系有三种，性质完全不同，不能混为一谈：

| 类型 | 含义 | 严重度 |
|---|---|---|
| **真矛盾 / 方向反转** | 初期说的和现在做的字面相反（如放弃清单说了不做、现在做了） | 高，面试会被直接打穿 |
| **优先级漂移** | 初期写"以后做"，现在做了或永久不做；不是错，但文稿没更新 | 中 |
| **新增内容无对应条款** | v2.0 加了初期文稿里根本没有的东西，文稿成了过时文档 | 低，但要补 |

## A. 会被面试官直接读成"自相矛盾"的（优先处理）

### A1 「不自动联网搜价」 vs 行业参考区间锚点 ← 你举的例子

**初期依据**
- 《产品初步描述.docx》「MVP版本放弃」第 2 条：*AI 自动联网搜索 PDD/淘宝/闲鱼等当日最新价格，由用户手动输入或发送截图*。
- 同文「明确输入、输出的条件」：可选填写 = **今日查询到的**全新款/二手价格 → 即"行情由用户自己去查"。
- 这条在 v2.0 也原样保留：`PRD §3.3`「AI 自动联网搜索当日最新二手价」仍在"明确不做"里；`design.html` 取舍③「明确不做」也写着。

**v2.0 事实**
- 新增参考回收率锚点，**主动**展示「品类 × 持有年限段」的行业区间 + 按实付折算的金额区间（`PRD §5.5`、`design.html` 取舍⑤、`benchmark-data.js`）。

**判定：不是硬违反，但字面一定会被读成违反。**
锚点是**人工核过出处后硬编码的静态表**（`PRD §6.1` 已写明），它：① 不联网、不实时；② 不针对"你这台设备"；③ 不可一键填入。三点都与"自动搜价"相反。问题是这三点的区别只散落在 PRD/design 里，**初期文稿那一句"放弃搜价"还是孤零零地立着**，读者先看到放弃清单、后看到锚点，第一反应就是"你自己打自己"。

**建议改法（分层，不删原意）**
把初期文稿放弃清单第 2 条改写为版本分层的表述：

> 1.0：不做自动搜价。二手价一律由用户手动输入或用订单截图识别。
> 2.0：新增行业参考区间——**静态硬编码、不联网、不实时、不针对具体设备、不可代填**。
> 它回答"这个品类大概落在什么区间"，不回答"你这台值多少"。
> **实时联网抓当日行情，仍属不做。**

同时给 `PRD §3.3` 那一条加一行交叉引用（"与锚点的区别见 §5.5"），避免两处孤立。

**已落地改动（2026-10-09，作者拍板后执行）** ✅

1. `产品初步描述.docx`「MVP版本放弃」第 2 条改写为版本分层：
   - 2.AI 自动联网搜索 PDD/淘宝/闲鱼等当日最新价格，改为由用户手动输入或发送截图。
     - 1.0：不做自动联网搜价；二手价一律由用户手动输入或用订单截图识别。
     - 2.0：新增"行业参考区间"（锚点）——人工核对出处后硬编码的静态表，不联网、不实时、

       不回答"你这台值多少"。
     - **目的**：给用户一个参照系。否则用户看到的回收率只是一个孤立的百分数，
       无从判断"这算好还是不好"。
     - 始终不做：实时联网抓取当日行情。
   - 顺带修掉原稿的排版错误：第 2、3 条原本黏在同一段（夹着错乱的"截图3."），已拆为两段。
   - 原文备份：`产品初步描述.bak-20261009.docx`。
2. `PRD §3.3` "AI 自动联网搜索当日最新二手价"一条加注：**此条仅指"实时联网抓取"**，
   与 §5.5 的静态锚点不是一回事。
3. `PRD §5.5` 补一句"为什么要给旁证"（参照系，不是"你这台值多少"）。

### A2 "首版最重要的结果 = 估算保值率"这项消失了，且从未交代

**初期依据**
- 《产品初步描述.docx》「首版最重要的结果应该是什么：**日均成本、估算保值率**」。
- 同文 P0 第 7 项含「**价格类型**」；「明确输入、输出的条件」里专门定义了「今日查询到的**全新款**价格是通用价格，不含特殊优惠券」。

**v2.0 事实**
- 交付结果里没有"保值率"，只有 **按实付回收率（S ÷ P）**（`PRD §5.2`、`site/README.md` 计算口径）。
- 也**没有"全新款价格"这个字段**，从来就没有。
- 而 v2.0 的锚点恰恰把两者的差异摆上了台面：*行业保值率多按发售价统计……本工具回收率按实付算*（`design.html` 取舍⑤、`PRD §5.5`）——**等于承认"保值率"和"回收率"不是一回事**，却始终没回头解释"为什么首版写保值率、最后变成回收率、全新价字段去哪了"。

**判定：真矛盾（口径与术语漂移），且是"首版最重要结果"级别的，面试官翻初期文稿必问。**

**建议改法**
在 `PRD §5` 或 `design.html` 补一段口径演进，明写：

> 初期把"估算保值率"列为首版重要结果，需要"全新款价格"做分母。落地时改为**按实付回收率（S/P）**：
> 保值率的口径依赖全新价（且市面行业值多按发售价、回收商报价，口径不统一），而回收率分母是用户自己填的实付，**口径唯一、可复现、与用户实际支出对齐**。
> 配套的"全新款价格"输入字段随之取消。

**已落地改动（2026-10-09，作者拍板后执行）** ✅

作者的决策与清单建议不同：**不补"口径演进说明"，而是把首版里从未落地的表述直接删干净**，让初期文稿与 v2.0 实现完全一致，不留"承诺过又蒸发"的痕迹。
（这也一并解决了 A3。）

| 位置 | 改动 |
|---|---|
| 「首版最重要的结果应该是什么」 | "日均成本、**估算保值率**" → "日均成本、**按实付回收率**"（首版全文本来就用"回收率"，只有这一处写"保值率"，改后内部自洽） |
| P0 第 7 项 | "公式、**价格类型**、计算假设；" → "公式、计算假设；" |
| 「可选填写的」 | "今日查询到的**全新款／二手**的价格" → "今日查询到的**二手成交价**" |
| 「可选填写的」细则 1 | **整条删除**（"填写的【查询到的全新款】是通用价格，不包含单独特殊的优惠券等。"） |
| 「可选填写的」细则 2 | 编号 "2." → "1."（前一条删掉后重排） |

初期 P1：*订单截图识别 / 识别结果确认和修改 / 价格区间 / 多台设备记录 / 价格来源链接和查询日期*。

### B2 初期 P1 的"价格来源/查询日期"与锚点自带的"来源 + 数据时间"撞名，容易被读成打架

- 初期要的是：**让用户登记他自己是从哪查的价、什么时候查的**。
- 锚点给的是：**我的行业数据的出处与时间**（`PRD §5.5`、`benchmark-data.js`）。
- 两个"来源/时间"名字几乎一样，指的东西完全不同。

**建议改法**：在锚点说明里加一句"这里的来源与时间指行业数据的出处，不是要你登记从哪查的价"，或统一换词（如"数据出处" vs "查询记录"），避免同一页出现两个"来源/日期"。

### B3 "多台设备记录"从 P1 升为 v2.0 核心，理由只在案例复盘里

- 升格理由写得很好，但只存在于 `案例复盘 Q5`（"不是把 P1 提前，是它从对比功能变成记录能力"）。
- 初期文稿和 `PRD` 都没在"多台设备记录"这一条上留痕。

**建议改法**：在 PRD/初期文稿对应条目补一句升格理由 + 那条硬约束："记录功能不能占用输入漏斗任何一步"。

## C. 新增内容在初期文稿里没有对应条款（文稿缺章）

v2.0 的账本、锚点、衰减曲线、设备品类，在初期文稿里全都**没有对应章节**。这不是矛盾，是"输入文档没跟上"，但要让读者看得出来是有意补的。

### C1 账本 = 全新数据形态，初期文稿没有任何"留存/记录"概念
- 初期隐私只写「只收集计算所需字段，不收集姓名、地址、手机号、订单号」——**没有覆盖"用户主动记录的本地留存"这一层**。
- v2.0 账本把"买过什么、花了多少、持有多久"写进 `localStorage`，持久化。
- **建议**：在初期文稿隐私段或 PRD 指向 v2.0 的精确化表述（`PRD §7.3`：*填入的数字不上传；主动记入账本的记录只存在你的浏览器里*），把"本地留存"显式纳入，而不是让读者以为隐私条款只覆盖服务端收集。

### C2 "设备品类"是输入区新增的第 4 个字段，与"减少填写负担"有张力
- 初期：*必填项尽量少：日期和买入价即可获得第一个结果*；输入区是"连续表单"，字段只有 名称/日期/金额 三个。
- v2.0：输入区新增「设备品类」（选填、默认"自动识别"、可手动改，`P0-12`）。
- **判定**：不违反必填原则（选填、不阻塞、不填也能算），但**输入区字段数从 3 变 4**，与"减少填写负担"的精神存在张力。
- **建议**：写清"品类为选填、默认自动推断、可不填；**必填项数量未变，仍为日期 + 实付金额**"，把张力显式化。

### C3 "衰减曲线"与初期"历史成本曲线"的关系，只有 PRD 注释提到
- `PRD §3.2` 注：v1.0 P1 里的"历史成本曲线"落地为**日均衰减曲线（P÷D 随天数下降）**，不是"历史价格走势"。
- 这条只在 PRD 一处，初期文稿没有。
- **建议**：初期文稿对应条目加同一句指向，防止"曲线"被读成价格走势图（那又回到"搜价"那条不做的事上）。

### C4 初期流程图已缺"账本"节点
- 初期流程图：手动输入 → 基础结果 → 补充售价 → 净成本/回收率 → 查看口径并反馈（5 步）。
- v2.0：完整结果后新增「我的账本」分区，且「记入账本」按钮出现在基础结果区（`PRD §4`、`信息架构`）。
- **建议**：更新流程图或加注"v2.0 在反馈之后新增账本分区"。
